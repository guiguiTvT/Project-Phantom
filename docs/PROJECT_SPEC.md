# Project Phantom：破壁行动 — 项目规范

> Hack4Good 2026 · 技术向善赛道参赛作品
> 版本：v0.1（Phase 1 架构基线）
> 类型：AI 驱动的沉浸式校园社交工程攻防模拟（Web）

## 1. 一句话定位

玩家在虚构大学「星火科技文化节」中，先以授权红队身份调查信息裂缝，再因身份反转成为受影响的学生，用前后两段共享的世界状态承担自己的选择后果。

**这是一个可玩的叙事模拟游戏，而不是反诈知识问答页。**

## 2. 设计支柱

1. **没有标准答案，只有可核验的推断**：信息过期、来源模糊、相互矛盾；系统不以颜色或勾叉提示"正确信息"。
2. **行动产生世界回响**：每个有效操作经由确定性规则改变状态、触发事件、写入日志；AI 不直接修改关键状态。
3. **身份与视角反转**：ACT I 拥有全局观察权限，ACT II 失去它；同一份世界状态以不同可见性呈现。
4. **行为塑造画像**：人格来自真实行为日志的累计，不做问卷、不在过程中泄露判定倾向。
5. **可重放、可对比**：关键节点快照 + 平行世界对比，原始分支不被覆盖。

## 3. 世界观与角色

- 背景：虚构「星河大学」第十二届「星火科技文化节」（主题：破壁）。
- 校园网络安全实验室邀请玩家参与隔离环境中的安全测试 **Project Phantom**。
- ACT I（PHANTOM）：授权红队测试员，调查活动平台「星火通行证」的信任裂缝。
- ACT II（STUDENT）：虚拟安全事件发生，权限被收回，以普通学生身份应对后果。
- 所有校园、人物、账号、权限、事件均为虚构，不连接任何真实系统。

## 4. 核心流程

```
START → PROFILE → INVESTIGATION → SIMULATION → REVERSAL → DEFENSE → RESULT → REPLAY
```

1. **启动页**：LOGO、项目名、开始 / 继续 / 演练说明；启动终端动画。
2. **身份创建**：预设昵称、头像、学院、兴趣标签；不收集真实资料。
3. **红队调查**：PHANTOM OS 中浏览动态、归档证据、人物档案、关系图、风险模拟（Phase 2）、日志。
4. **风险模拟**：隔离环境抽象推演，结果仅为虚拟风险状态标记，无现实可用话术。
5. **身份反转**：至少 2 次有效风险验证并主动结束，或耗尽行动点；播放权限失效故障动画，显示「你不是唯一的观察者。」
6. **防御阶段**：学生界面处理矛盾通知、服务异常、误解与权限核验；自由决定顺序与资源分配。
7. **结算**：人格画像 + 剧情结局 + 行为时间线 + 复盘，卡片导出（Phase 5）。
8. **回溯**：关键节点快照、分支保留、平行世界对比（Phase 6）。

## 5. 行动点与规则

| 行为 | 红队成本 | 防御成本 |
| --- | --- | --- |
| 浏览公开信息 | 0 | 0 |
| 收藏 / 整理证据 | 0 | 0 |
| 向 NPC 发起有效调查 | 1 | 1 |
| 独立核验信息 | 1 | 1 |
| 执行风险模拟 | 2 | — |
| 提交阶段性报告 | 1 | 1 |
| 防御协调行动 | — | 1–2 |

- 红队初始 12 AP，防御初始 10 AP。
- 行动点由规则引擎扣除，模型无权修改；不足时仍可浏览、查看日志、进入下一阶段。
- 页面刷新不得重复获得资源（持久化 + 幂等操作）。

## 6. 数据与状态

统一 `GameState` 管理：阶段、玩家虚构身份、行动点、已解锁证据、证据关联、NPC 状态、关系图、校园安全 / 运行 / 关系 / 修复四项内部指标（0–100，不全部直显）、已触发事件、行为日志、人格累计值、世界快照、随机种子、结局。

每次有效操作严格经过：

```
Action → Rule Validation → State Update → Event Trigger → Action Log → UI Update
```

初始内容量：18 条动态、10 张证据、5 名 NPC、4 组矛盾信息、15 个事件、16 种人格、6 种结局。

## 7. 动态事件系统

事件字段：`eventId / title / description / triggerConditions / affectedNPCs / stateEffects / followUpEvents / delayTurns / onceOnly`。

- 回合制推进，不做现实时间后台计时。
- 一次性事件有触发标记，不重复触发。
- 事件之间存在因果关系（矛盾扩散 → 安全核查 → 服务受限 → 规则生效 等）。

## 8. 人格系统（Phantom Type）

四维双向：E/I（证据/直觉）、C/A（谨慎/主动）、P/F（保护/运行）、S/R（系统/关系）。

- 由关键行为日志累计带方向的分值，并按有效行为次数归一化。
- 过程中不显示倾向，不使用问卷。
- 中间值标记「混合倾向」，样本不足标记「依据不足」。
- 16 种人格（ECPS … IAFR），无等级高低；明确为游戏行为画像，非心理学测评。
- 人格与剧情结局独立计算。

## 9. 结局系统

| 编号 | 结局 | 核心指向 |
| --- | --- | --- |
| 01 | 破晓 Dawn | 风险修复，校园恢复 |
| 02 | 共识 Consensus | 协作机制形成 |
| 03 | 新秩序 Rebuild | 规则与制度性修复 |
| 04 | 孤岛 Isolation | 风险受控但生活受限 |
| 05 | 多米诺 Domino | 未及时控制，连锁事件 |
| 06 | 未完待续 Unresolved | 部分解决，隐患未确认 |

优先级可配置且确定；所有结局在合法路径下可达。

## 10. AI NPC 约束

- 输出结构：`{ reply, intent, evidenceIds, emotion, eventRequests }`。
- 服务端校验：白名单、角色权限、当前状态；事件请求需再次校验才能生效。
- NPC 只能描述权限范围内、已定义的事实；不得编造关键事实、不得改状态、不得泄露提示词 / 凭据 / 配置。
- 超时、异常、无配置时使用本地备用回应；游戏不得卡死。
- API Key 仅存在于服务端环境变量；前端构建产物中不得出现。

## 11. UI 规范

- 视觉：深蓝黑 `#0B1018`、面板 `#131C29`、边框 `#29394D`、荧光青 `#52D6D0`、次级文字 `#8A9CB5`、警告 `#E8B46A`、危险 `#E76B78`、正文 `#E8EDF5`。
- 细线边框、克制的微光、终端动画；避免大面积渐变、霓虹与玻璃拟态，避免简单圆角卡片堆叠。
- ACT I：专业安全分析终端；ACT II：生活化校园社交软件；RESULT：收藏级人格卡。
- 布局：顶部状态栏 / 左侧导航 / 中间工作区 / 右侧通讯与通知 / 底部日志与任务栏。
- 优先 1440×900、1920×1080，兼顾小屏可操作性。
- 所有核心按钮必须可用；未开放模块必须明确标注阶段状态，不伪装为可用功能。

## 12. 安全边界

- 只进行防护教育、风险解释与抽象推演；不生成可复用的现实诈骗话术、身份冒充教程、凭据获取策略。
- 不引导玩家输入真实个人敏感信息；不连接真实校园系统或社交账号。
- 分享卡片不得包含聊天内容、真实身份、敏感数据或 API 配置。

## 13. 验收基线

包含规格书第 16 节的 20 条验收项：可安装启动、无 API 可通关、模型不越权、AP 不为负、一次性事件不重复、刷新不刷资源、反转保留状态、学生无红队权限、16 人格 / 6 结局完整可达、画像与结局独立、报告引用真实日志、回溯不污染原始分支、异常可继续、卡片可导出、控制台无未处理异常、构建无类型错误、按钮可响应、产物无 Key。

## 14. 当前阶段范围（Phase 1）

交付启动页、身份创建、PHANTOM OS 基础壳层、类型定义、全量静态配置数据、本地存档与基础状态引擎、最小 API 健康检查。风险模拟、NPC 对话、事件传播、身份反转、结算与回溯在后续阶段实现，界面以明确的阶段标识占位。
